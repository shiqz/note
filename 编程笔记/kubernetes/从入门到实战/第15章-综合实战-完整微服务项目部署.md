# 第15章 综合实战：完整微服务项目部署

## 学习目标

通过本章的完整实战演练，你将能够：

1. 从零开始部署一个包含 Nginx 前端 + Go API 后端 + MySQL 数据库 + Redis 缓存的完整 Web 应用
2. 掌握 StatefulSet 与 Deployment 的使用场景差异
3. 学会为有状态应用配置持久化存储（StorageClass + PV/PVC）
4. 理解 Headless Service 与普通 Service 的区别和配合使用
5. 掌握 ConfigMap 与 Secret 在实际项目中的应用
6. 学会配置 HPA 自动扩缩容应对流量波动
7. 掌握 Ingress 路径路由配置实现前后端分离
8. 学会使用 Helm 快速部署监控系统（Prometheus + Grafana）
9. 掌握常见故障排查方法和灾难恢复演练
10. 具备独立搭建完整生产级 K8s 应用的能力

## 15.2 步骤1：创建项目 Namespace

Namespace 是资源隔离的基础，我们先创建一个名为 `myapp` 的命名空间。

```yaml
# namespace.yaml
apiVersion: v1
kind: Namespace
metadata:
  name: myapp
  labels:
    app: myapp
    environment: production
    version: v1.0
```

```bash
# 创建 Namespace
kubectl apply -f namespace.yaml

# 验证 Namespace 创建成功
kubectl get namespace myapp

# 设置当前操作的 Namespace（可选，方便后续操作）
kubectl config set-context --current --namespace=myapp

# 确认切换成功
kubectl config view | grep namespace
# 输出: namespace: myapp
```

## 15.3 步骤2：部署 MySQL

MySQL 是有状态应用，使用 **StatefulSet** 部署，配合持久化存储保证数据安全。

### 15.3.1 创建 StorageClass

```yaml
# storageclass.yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: myapp-sc
  namespace: myapp
provisioner: kubernetes.io/no-provisioner  # Minikube 用此；Kind 用 rancher.io/local-path
# 注意：不同环境 provisioner 不同
# Minikube: kubernetes.io/no-provisioner
# Kind:     rancher.io/local-path
# GKE:      kubernetes.io/gce-pd
# AWS EBS:  kubernetes.io/aws-ebs
parameters:
  type: pd-standard
  fsType: ext4
reclaimPolicy: Retain  # 保留数据，删除 PVC 时不会删除 PV
volumeBindingMode: WaitForFirstConsumer
```

```bash
# 创建 StorageClass
kubectl apply -f storageclass.yaml

# 或直接使用集群默认的 StorageClass
kubectl get storageclass
# 如果已有默认 SC，可跳过此步
```

### 15.3.2 创建 MySQL Secret

```yaml
# mysql-secret.yaml
apiVersion: v1
kind: Secret
metadata:
  name: mysql-secret
  namespace: myapp
  labels:
    app: myapp
    component: mysql
type: Opaque
stringData:
  # root 用户密码
  root-password: "RootPassword123!"
  # 业务用户密码
  database-password: "AppPassword456!"
  # 业务用户名
  database-user: "myapp_user"
  # 数据库名
  database-name: "myapp_db"
```

```bash
# 创建 Secret
kubectl apply -f mysql-secret.yaml

# 验证 Secret
kubectl get secret mysql-secret -n myapp
kubectl describe secret mysql-secret -n myapp

# 查看 Secret 中的值（base64 解码）
kubectl get secret mysql-secret -n myapp -o jsonpath='{.data.root-password}' | base64 -d
# 输出: RootPassword123!
```

### 15.3.3 创建 MySQL ConfigMap

```yaml
# mysql-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: mysql-config
  namespace: myapp
  labels:
    app: myapp
    component: mysql
data:
  my.cnf: |
    [mysqld]
    default_authentication_plugin=mysql_native_password
    max_connections=200

```


### 15.3.4 创建 MySQL StatefulSet + Service

```yaml
# mysql-statefulset.yaml
apiVersion: v1
kind: Service
metadata:
  name: myapp-mysql
  namespace: myapp
  labels:
    app: myapp
    component: mysql
spec:
  type: ClusterIP
  selector:
    app: myapp
    component: mysql
  ports:
    - name: mysql
      port: 3306
      targetPort: 3306
---
apiVersion: v1
kind: Service
metadata:
  name: myapp-mysql-hs
  namespace: myapp
  labels:
    app: myapp
    component: mysql
spec:
  clusterIP: None  # Headless Service
  selector:
    app: myapp
    component: mysql
  ports:
    - name: mysql
      port: 3306
      targetPort: 3306
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: myapp-mysql
  namespace: myapp
  labels:
    app: myapp
    component: mysql
spec:
  serviceName: myapp-mysql-hs
  replicas: 1  # 单机版（学习阶段使用）
  selector:
    matchLabels:
      app: myapp
      component: mysql
  template:
    metadata:
      labels:
        app: myapp
        component: mysql
    spec:
      containers:
        - name: mysql
          image: mysql:8.0
          ports:
            - containerPort: 3306
              name: mysql
          env:
            - name: MYSQL_ROOT_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: mysql-secret
                  key: root-password
            - name: MYSQL_DATABASE
              valueFrom:
                secretKeyRef:
                  name: mysql-secret
                  key: database-name
            - name: MYSQL_USER
              valueFrom:
                secretKeyRef:
                  name: mysql-secret
                  key: database-user
            - name: MYSQL_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: mysql-secret
                  key: database-password
          volumeMounts:
            - name: mysql-data
              mountPath: /var/lib/mysql
            - name: mysql-config
              mountPath: /etc/mysql/conf.d
          resources:
            requests:
              memory: "256Mi"
              cpu: "250m"
            limits:
              memory: "512Mi"
              cpu: "500m"
          readinessProbe:
            exec:
              command:
                - mysqladmin
                - ping
                - -h
                - localhost
                - -u
                - root
                - -p$(MYSQL_ROOT_PASSWORD)
            initialDelaySeconds: 10
            periodSeconds: 5
            timeoutSeconds: 2
            failureThreshold: 3
          livenessProbe:
            exec:
              command:
                - mysqladmin
                - ping
                - -h
                - localhost
                - -u
                - root
                - -p$(MYSQL_ROOT_PASSWORD)
            initialDelaySeconds: 30
            periodSeconds: 10
            timeoutSeconds: 5
            failureThreshold: 3
      volumes:
        - name: mysql-config
          configMap:
            name: mysql-config
            items:
              - key: my.cnf
                path: my.cnf
  volumeClaimTemplates:
    - metadata:
        name: mysql-data
      spec:
        accessModes:
          - ReadWriteOnce
        storageClassName: myapp-sc
        resources:
          requests:
            storage: 5Gi
```

```bash
# 部署 MySQL
kubectl apply -f mysql-statefulset.yaml

# 等待 MySQL Pod 就绪（StatefulSet Pod 按顺序创建）
kubectl get pods -n myapp -w
# myapp-mysql-0 状态应为 Running，READY 为 1/1

# 验证 MySQL 服务
kubectl get svc -n myapp
# 应看到 myapp-mysql (ClusterIP) 和 myapp-mysql-hs (None)

# 进入 MySQL Pod 验证数据库
kubectl exec -it myapp-mysql-0 -n myapp -- mysql -u root -p'RootPassword123!' -e "SHOW DATABASES;"
# 应显示 myapp_db 数据库已创建

# 验证业务用户
kubectl exec -it myapp-mysql-0 -n myapp -- mysql -u myapp_user -p'AppPassword456!' -e "USE myapp_db; SELECT 1;"
# 应返回 +---+
# | 1 |
# +---+
```

## 15.4 步骤3：部署 Redis

### 15.4.1 创建 Redis ConfigMap

```yaml
# redis-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: redis-config
  namespace: myapp
  labels:
    app: myapp
    component: redis
data:
  redis.conf: |
    # 基础配置
    port 6379
    bind 0.0.0.0
    protected-mode no
    # 内存管理
    maxmemory 128mb
    maxmemory-policy allkeys-lru
    # 持久化 - RDB
    save 900 1
    save 300 10
    save 60 10000
    stop-writes-on-bgsave-error yes
    rdbcompression yes
    rdbchecksum yes
    dbfilename dump.rdb
    dir /data
    # 持久化 - AOF
    appendonly yes
    appendfilename "appendonly.aof"
    appendfsync everysec
    no-appendfsync-on-rewrite no
    auto-aof-rewrite-percentage 100
    auto-aof-rewrite-min-size 64mb
    # 日志
    loglevel notice
    # 网络
    tcp-keepalive 300
    timeout 0
    # 客户端
    maxclients 10000
```

```bash
kubectl apply -f redis-configmap.yaml
```

### 15.4.2 创建 Redis Deployment + Service

```yaml
# redis-deployment.yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: redis-data
  namespace: myapp
  labels:
    app: myapp
    component: redis
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: myapp-sc
  resources:
    requests:
      storage: 1Gi
---
apiVersion: v1
kind: Service
metadata:
  name: myapp-redis
  namespace: myapp
  labels:
    app: myapp
    component: redis
spec:
  type: ClusterIP
  selector:
    app: myapp
    component: redis
  ports:
    - name: redis
      port: 6379
      targetPort: 6379
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp-redis
  namespace: myapp
  labels:
    app: myapp
    component: redis
spec:
  replicas: 1
  selector:
    matchLabels:
      app: myapp
      component: redis
  template:
    metadata:
      labels:
        app: myapp
        component: redis
    spec:
      containers:
        - name: redis
          image: redis:7-alpine
          ports:
            - containerPort: 6379
              name: redis
          command:
            - redis-server
            - /etc/redis/redis.conf
          volumeMounts:
            - name: redis-data
              mountPath: /data
            - name: redis-config
              mountPath: /etc/redis
          resources:
            requests:
              memory: "128Mi"
              cpu: "100m"
            limits:
              memory: "256Mi"
              cpu: "250m"
          readinessProbe:
            exec:
              command:
                - redis-cli
                - ping
            initialDelaySeconds: 5
            periodSeconds: 5
          livenessProbe:
            exec:
              command:
                - redis-cli
                - ping
            initialDelaySeconds: 15
            periodSeconds: 10
      volumes:
        - name: redis-data
          persistentVolumeClaim:
            claimName: redis-data
        - name: redis-config
          configMap:
            name: redis-config
            items:
              - key: redis.conf
                path: redis.conf
```

```bash
# 部署 Redis
kubectl apply -f redis-deployment.yaml

# 等待 Redis Pod 就绪
kubectl get pods -n myapp -l component=redis -w

# 验证 Redis 可用
kubectl exec -it myapp-redis-<pod-name> -n myapp -- redis-cli ping
# 输出: PONG

# 测试基本操作
kubectl exec -it myapp-redis-<pod-name> -n myapp -- redis-cli set test_key "hello myapp"
kubectl exec -it myapp-redis-<pod-name> -n myapp -- redis-cli get test_key
# 输出: "hello myapp"

# 测试持久化
kubectl exec -it myapp-redis-<pod-name> -n myapp -- redis-cli save
# 重启 Pod 后数据仍在
```

## 15.5 步骤4：准备后端 API 服务

### 15.5.1 创建后端 ConfigMap

```yaml
# backend-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: backend-config
  namespace: myapp
  labels:
    app: myapp
    component: backend
data:
  app.properties: |
    # 应用配置
    app.name=MyApp API
    app.version=1.0.0
    app.environment=production
    app.log.level=info

    # 服务器配置
    server.port=8080
    server.address=0.0.0.0

    # MySQL 数据库配置
    db.host=myapp-mysql
    db.port=3306
    db.name=myapp_db
    db.username=myapp_user
    # 密码通过 Secret 注入
    db.pool.max=50
    db.pool.idle=10
    db.pool.timeout=30

    # Redis 缓存配置
    redis.host=myapp-redis
    redis.port=6379
    redis.db=0
    redis.timeout=5
    redis.key.prefix=myapp:

    # 缓存过期时间（秒）
    cache.ttl.short=300
    cache.ttl.medium=1800
    cache.ttl.long=86400

    # API 配置
    api.rate.limit=100
    api.rate.window=60
    api.cors.origins=*
```

```yaml
# backend-secret.yaml
apiVersion: v1
```

### 15.5.3 创建后端 Deployment + Service

```yaml
# backend-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp-backend
  namespace: myapp
  labels:
    app: myapp
    component: backend
spec:
  replicas: 2
  selector:
    matchLabels:
      app: myapp
      component: backend
  template:
    metadata:
      labels:
        app: myapp
        component: backend
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/port: "8080"
        prometheus.io/path: "/metrics"
    spec:
      # 使用 init container 等待数据库就绪
      initContainers:
        - name: wait-for-mysql
          image: mysql:8.0
          command:
            - sh
            - -c
            - |
              echo "Waiting for MySQL to be ready..."
              until mysql -h myapp-mysql -u myapp_user -p"$DB_PASSWORD" -e "SELECT 1" myapp_db; do
                echo "MySQL is not ready yet. Retrying in 2 seconds..."
                sleep 2
              done
              echo "MySQL is ready!"
          env:
            - name: DB_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: backend-secret
                  key: db-password
        - name: wait-for-redis
          image: redis:7-alpine
          command:
            - sh
            - -c
            - |
              echo "Waiting for Redis to be ready..."
              until redis-cli -h myapp-redis ping | grep -q PONG; do
```

```yaml
# nginx-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: nginx-config
  namespace: myapp
  labels:
    app: myapp
    component: frontend
data:
  nginx.conf: |
    user nginx;
    worker_processes auto;
    error_log /var/log/nginx/error.log warn;
    pid /var/run/nginx.pid;

    events {
        worker_connections 1024;
        multi_accept on;
    }

    http {
        include /etc/nginx/mime.types;
        default_type application/octet-stream;

        # 日志格式
        log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                        '$status $body_bytes_sent "$http_referer" '
                        '"$http_user_agent" "$http_x_forwarded_for"';

        access_log /var/log/nginx/access.log main;

        # 性能优化
        sendfile on;
        tcp_nopush on;
        tcp_nodelay on;
        keepalive_timeout 65;
        types_hash_max_size 2048;
        client_max_body_size 50m;

        # 压缩
        gzip on;
        gzip_vary on;
        gzip_proxied any;
        gzip_comp_level 6;
        gzip_types text/plain text/css application/json application/javascript
                   text/xml application/xml application/xml+rss text/javascript;

        # 上游：后端 API 服务
        upstream backend_api {
            server myapp-backend:8080;
            keepalive 32;
        }

        server {
            listen 80;
            server_name _;

            # 静态文件服务
            root /usr/share/nginx/html;
            index index.html;

            # 健康检查端点
            location = /health {
                access_log off;
                return 200 'OK';
                add_header Content-Type text/plain;
            }

            # API 反向代理
            location /api/ {
                proxy_pass http://backend_api/;
                proxy_http_version 1.1;
                proxy_set_header Host $host;
                proxy_set_header X-Real-IP $remote_addr;
                proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
                proxy_set_header X-Forwarded-Proto $scheme;
                proxy_set_header Connection "";

                # 超时配置
                proxy_connect_timeout 30s;
                proxy_send_timeout 30s;
                proxy_read_timeout 60s;

                # 缓冲区配置
                proxy_buffer_size 4k;
                proxy_buffers 8 4k;
            }

            # WebSocket 支持（如需要）
            location /ws/ {
                proxy_pass http://backend_api/ws/;
                proxy_http_version 1.1;
                proxy_set_header Upgrade $http_upgrade;
                proxy_set_header Connection "upgrade";
                proxy_set_header Host $host;
            }

            # 前端路由支持（SPA）
            location / {
                try_files $uri $uri/ /index.html;
            }

            # 静态资源缓存
            location ~* \.(?:css|js|jpg|jpeg|png|gif|ico|svg|woff|woff2|ttf|eot)$ {
                expires 30d;
                add_header Cache-Control "public, immutable";
                access_log off;
            }
        }
    }
```

```yaml
# hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: myapp-backend-hpa
  namespace: myapp
  labels:
    app: myapp
    component: backend
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: myapp-backend
  minReplicas: 2
  maxReplicas: 10
  metrics:
    # CPU 使用率
    - type: Resource

        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
    # 内存使用率
    - type: Resource
      resource:
        name: memory
        target:
          type: Utilization
          averageUtilization: 80
  behavior:
    scaleUp:
      stabilizationWindowSeconds: 60
      policies:
        - type: Percent
          value: 100
          periodSeconds: 30
        - type: Pods
          value: 2
          periodSeconds: 60
      selectPolicy: Max
    scaleDown:
      stabilizationWindowSeconds: 300
      policies:
        - type: Percent
          value: 50
          periodSeconds: 60
      selectPolicy: Min
```

```yaml
            backend:
```

## 15.15 章节小结与学习建议

### 15.15.1 本章小结

本章我们完成了一个完整的 **微服务项目实战**，涵盖了 Kubernetes 生产级部署的方方面面：

| 知识点 | 应用场景 | 本章实践 |
|--------|----------|----------|
| **Namespace** | 资源隔离 | 创建 `myapp` 命名空间，隔离所有项目资源 |
| **StatefulSet** | 有状态应用 | MySQL 集群部署，保证 Pod 顺序和稳定网络标识 |
| **Deployment** | 无状态应用 | Redis、Nginx、Go API 部署，支持滚动更新 |
| **ConfigMap** | 配置管理 | MySQL、Redis、Nginx、后端应用配置 |
| **Secret** | 敏感信息 | 数据库密码、API 密钥、JWT 密钥 |
| **Service** | 网络通信 | ClusterIP 服务、Headless Service、NodePort |
| **PVC/PV** | 持久化存储 | MySQL 数据、Redis 数据持久化 |
| **StorageClass** | 动态供给 | 统一存储管理，支持多环境切换 |
| **HPA** | 自动扩缩容 | 后端 API 基于 CPU/内存自动扩缩 |
| **Ingress** | 流量路由 | 路径路由：/ → 前端，/api → 后端 |
| **RBAC** | 权限控制 | 监控只读权限、后端 API 最小权限 |
| **initContainer** | 启动依赖 | 等待 MySQL/Redis 就绪再启动后端 |
| **探针** | 健康检查 | readinessProbe + livenessProbe 保障服务健康 |
| **资源限制** | 资源管理 | requests/limits 防止资源争抢 |
| **Helm** | 应用部署 | Prometheus + Grafana 一键部署 |
| **ServiceMonitor** | 指标采集 | 自动发现 Pod 指标 |
| **故障恢复** | 高可用 | Pod 重建、节点迁移、数据恢复 |

### 15.15.4 常见问题速查

| 问题 | 解决方案 |
|------|----------|
| Pod 一直 Pending | 检查资源是否充足、节点污点/容忍、调度约束 |
| Pod CrashLoopBackOff | 查看 `kubectl logs --previous` 找崩溃日志 |
| MySQL 无法连接 | 检查 Service/Endpoints、init container、网络连通 |
| HPA 显示 `<unknown>` | 确认 Metrics Server 正常，等待 1-2 分钟 |
| Ingress 不生效 | 检查 Ingress Controller、注解、路由规则 |
| PVC 一直 Pending | 检查 StorageClass、PV、存储插件状态 |
| RBAC 权限不生效 | 检查 Role/Subject 绑定、apiGroups/resources/verbs |
| ImagePullBackOff | 检查镜像名称、镜像仓库认证、网络 |
