## 2.1 方案对比与选型

### 2.1.1 四大主流方案

| 维度 | Minikube | Kind | k3s | Docker Desktop |
|------|----------|------|-----|---------------|
| 维护方 | CNCF 社区 | CNCF 社区 | SUSE/Rancher Labs | Docker Inc. |
| 运行方式 | 单 Node 虚拟机/容器 | 多 Node 容器 | 单二进制/容器 | 内置 K8s |
| 节点数 | 单节点 | 多节点（默认 1 控制面+1 工作节点） | 单节点 | 单节点 |
| 安装复杂度 | 低 | 低 | 极低 | 极低 |
| 资源占用 | 中 | 中 | 低 | 中 |
| 网络模型 | HostOnly | Docker 网络 | Flannel | Docker 网络 |
| 存储 | 临时/可选持久化 | 临时 | 本地 SQLite | 临时 |
| 适用场景 | 学习/开发/单节点测试 | 多节点拓扑测试/CI | 边缘计算/资源受限 | Docker 用户快速上手 |
| 生产就绪 | ❌ | ❌ | ✅ 轻量生产 | ❌ |

### 2.1.2 选型建议

```
你的需求是什么？
    │
    ├── 需要多节点集群测试（调度、亲和性等）？
    │       └── 是 → Kind
    │
    ├── 资源受限或边缘场景？
    │       └── 是 → k3s
    │
    ├── 已是 Docker Desktop 用户，不想额外安装？
    │       └── 是 → Docker Desktop K8s
    │
    └── 学习 K8s / 日常开发 / 单节点即可？
            └── 是 → Minikube（推荐本章重点学习）
```

### 2.1.3 方案详细对比

#### Minikube

- **特点**：老牌方案，功能丰富，支持多种驱动（Docker、HyperKit、VMware、VirtualBox、none）
- **优势**：内置 ingress、dashboard、metrics 等插件；支持 `addons` 扩展；社区活跃
- **劣势**：单节点；部分功能在容器驱动下受限

#### Kind（Kubernetes in Docker）

- **特点**：使用 Docker 容器作为 K8s 节点，支持多节点集群
- **优势**：原生支持多节点拓扑；CI/CD 友好；与 Docker 无缝集成
- **劣势**：集群启动速度较慢（30s+）；网络配置相对复杂

#### k3s

- **特点**：Rancher Labs 推出的轻量级 K8s 发行版，单二进制文件
- **优势**：极致轻量（<100MB 内存）；SQLite 替代 etcd；边缘场景首选
- **劣势**：非标准 K8s（使用 SQLite 而非 etcd）；兼容性需注意

#### Docker Desktop K8s

- **特点**：Docker Desktop 内置 K8s 支持，一键开启
- **优势**：零配置；与本地 Docker 共享镜像；适合 Docker 生态用户
- **劣势**：单节点；功能受限；依赖 Docker Desktop 许可证

## 2.2 Minikube 安装与配置

### 2.2.1 前置条件

```bash
# 检查 Docker 是否已安装
docker version

# 检查 Docker 是否在运行
docker info

# 如果 Docker 未安装，macOS 用户可通过 Homebrew 安装
brew install --cask docker

# 启动 Docker Desktop 后，等待 Docker 引擎就绪
docker info
```

### 2.2.2 macOS Intel 芯片安装

```bash
# 方式一：Homebrew 安装（推荐）
brew install minikube

# 验证安装
minikube version
# minikube version: v1.32.0

# 方式二：直接下载二进制文件
curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-darwin-amd64
sudo install minikube-darwin-amd64 /usr/local/bin/minikube

# 清理下载文件
rm minikube-darwin-amd64
```

### 2.2.3 macOS Apple Silicon 安装

```bash
# 方式一：Homebrew 安装（自动识别架构）
brew install minikube

# 验证安装
minikube version

# 方式二：直接下载 arm64 版本
curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-darwin-arm64
sudo install minikube-darwin-arm64 /usr/local/bin/minikube

# 清理下载文件
rm minikube-darwin-arm64
```

### 2.2.4 Linux 安装

```bash
# 下载并安装 Minikube
curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64
sudo install minikube-linux-amd64 /usr/local/bin/minikube

# 验证安装
minikube version

# 可选：安装自动补全
source <(minikube completion bash)
echo 'source <(minikube completion bash)' >> ~/.bashrc
```

### 2.2.5 Minikube 启动集群

```bash

minikube start --driver=docker
```

### 2.2.6 Minikube 常用命令

```bash
# 查看集群状态
minikube status

# 查看所有 profile
minikube profile list

# 切换 profile
minikube profile minikube-test

# 停止集群（保留数据）

# 启动已停止的集群
minikube start

# 删除集群（清理所有数据）
minikube delete

# 删除指定 profile
minikube delete -p minikube-test

# 查看 Minikube 日志
minikube logs

# 查看节点 IP
minikube ip

minikube ssh
```

### 2.2.7 Minikube 插件管理

```bash
# 查看已安装的插件

# 禁用插件

```

## 2.3 Kind 安装与配置

### 2.3.1 前置条件

```bash
# Kind 依赖 Docker，确保 Docker 已运行
docker info

# 建议 Docker 版本 >= 20.10
docker version --format '{{.Client.Version}}'
```

### 2.3.2 安装 Kind

**macOS（Intel & Apple Silicon）：**
```bash
# 使用 Homebrew 安装
brew install kind

# 或使用 go install
go install sigs.k8s.io/kind@latest

# 验证安装
kind version
# kind v0.20.0 darwin/arm64
```

**Linux：**
```bash
# 下载二进制文件
curl -Lo ./kind https://kind.sigs.k8s.io/dl/v0.20.0/kind-linux-amd64
chmod +x ./kind
sudo mv ./kind /usr/local/bin/kind

# 验证安装
kind version
```

### 2.3.3 创建单节点集群

```bash
# 创建默认单节点集群（1 控制面 + 0 工作节点）
kind create cluster

# 指定集群名称
kind create cluster --name dev-cluster

# 指定 K8s 版本
kind create cluster --name dev-cluster --image kindest/node:v1.29.2

# 指定 kubeconfig 路径
kind create cluster --name dev-cluster --kubeconfig ~/.kube/config-dev
```

### 2.3.4 创建多节点集群

```bash
# 创建多节点集群配置文件
cat > kind-multi-node.yaml << 'EOF'
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
  - role: worker
  - role: worker
  - role: worker
EOF

# 使用配置文件创建集群
kind create cluster --name prod-cluster --config kind-multi-node.yaml

# 验证多节点集群
kubectl get nodes
# NAME                              STATUS   ROLES           AGE   VERSION
# prod-cluster-control-plane        Ready    control-plane   30s   v1.29.2
# prod-cluster-worker               Ready    <none>          20s   v1.29.2
# prod-cluster-worker2              Ready    <none>          20s   v1.29.2
# prod-cluster-worker3              Ready    <none>          20s   v1.29.2
```

### 2.3.5 Kind 高级配置

```yaml
# kind-advanced.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
    extraPortMappings:
      - containerPort: 30000
        hostPort: 30000
        listenAddress: "0.0.0.0"
      - containerPort: 80
        hostPort: 8080
        listenAddress: "0.0.0.0"
    kubeadmConfigPatches:
      - |
        kind: InitConfiguration
        nodeRegistration:
          criSocket: "kind-control-plane-container//run/containerd/containerd.sock"
  - role: worker
  - role: worker

# 启用 Ingress
kind create cluster --name ingress-cluster \
  --config kind-advanced.yaml \
  --wait=5m

# 导出集群日志
kind export logs --name prod-cluster ./kind-logs
```

### 2.3.6 Kind 集群管理

```bash
# 列出所有 Kind 集群
kind get clusters

# 删除集群
kind delete cluster --name dev-cluster

# 加载本地镜像到集群
kind load docker-image my-app:v1 --name dev-cluster

# 加载镜像到指定节点
kind load docker-image my-app:v1 --name dev-cluster --nodes prod-cluster-worker

# 导出集群 kubeconfig
kind export kubeconfig --name dev-cluster --kubeconfig ~/.kube/config-dev
```

## 2.5 实战：部署第一个 Hello World 应用（Nginx）

### 2.5.1 创建 Nginx Pod

```bash
# 创建 Pod 定义文件
cat > nginx-pod.yaml << 'EOF'
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: nginx
    version: "1.25"
spec:
  containers:
    - name: nginx
      image: nginx:1.25
      ports:
        - containerPort: 80
          name: http
      resources:
        requests:
          memory: "64Mi"
          cpu: "100m"
        limits:
          memory: "128Mi"
          cpu: "250m"
      livenessProbe:
        httpGet:
          path: /
          port: 80
        initialDelaySeconds: 5
        periodSeconds: 10
      readinessProbe:
        httpGet:
          path: /
          port: 80
        initialDelaySeconds: 3
        periodSeconds: 5
EOF

# 部署 Pod
kubectl apply -f nginx-pod.yaml

# 观察 Pod 创建过程
kubectl get pods -w
```

### 2.5.2 创建 Service 暴露服务

```bash
# 创建 Service 定义文件
cat > nginx-svc.yaml << 'EOF'
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
  labels:
    app: nginx
spec:
  type: NodePort
  selector:
    app: nginx
  ports:
    - port: 80
      targetPort: 80
      nodePort: 30080
      name: http
EOF

# 部署 Service
kubectl apply -f nginx-svc.yaml

# 查看 Service 状态
kubectl get services
```

### 2.5.3 验证服务可访问

```bash
# 获取 Minikube IP
minikube ip
# 输出示例：192.168.64.2

# 方式一：直接访问 NodePort
curl http://$(minikube ip):30080

# 方式二：使用 kubectl port-forward（推荐本地开发）
kubectl port-forward service/nginx-service 8080:80
# 另开终端访问
curl http://localhost:8080

# 方式三：使用 minikube service 命令
minikube service nginx-service
# 该命令会自动打开浏览器

# 验证 Pod 正常响应
kubectl exec nginx-pod -- curl -s http://localhost:80
```

### 2.5.4 查看日志与诊断

```bash
# 查看 Nginx 访问日志
kubectl logs -f nginx-pod

# 查看 Pod 事件
kubectl describe pod nginx-pod

# 检查探针状态
kubectl get pod nginx-pod -o jsonpath='{.status.conditions}' | jq

# 检查 Endpoints
kubectl get endpoints nginx-service -o yaml

# 清理资源
kubectl delete -f nginx-svc.yaml
kubectl delete -f nginx-pod.yaml
```

### 2.5.5 使用 Deployment 管理应用（推荐方式）

```bash
# 创建 Deployment 定义文件
cat > nginx-deployment.yaml << 'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
  labels:
    app: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
        - name: nginx
          image: nginx:1.25
          ports:
            - containerPort: 80
          resources:
            requests:
              memory: "64Mi"
              cpu: "100m"
            limits:
              memory: "128Mi"
              cpu: "250m"
          livenessProbe:
            httpGet:
              path: /
              port: 80
            initialDelaySeconds: 5
            periodSeconds: 10
          readinessProbe:
            httpGet:
              path: /
              port: 80
            initialDelaySeconds: 3
            periodSeconds: 5
          lifecycle:
            preStop:
              exec:
                command: ["nginx", "-s", "quit"]
EOF

# 部署 Deployment
kubectl apply -f nginx-deployment.yaml

# 查看部署状态
kubectl get deployment nginx-deployment
kubectl get pods -l app=nginx

# 滚动升级
kubectl set image deployment/nginx-deployment nginx=nginx:1.26

# 查看升级状态
kubectl rollout status deployment/nginx-deployment

# 回滚到上一个版本
kubectl rollout undo deployment/nginx-deployment

# 扩缩容
kubectl scale deployment nginx-deployment --replicas=5

# 清理资源
kubectl delete -f nginx-deployment.yaml
```

## 2.6 常见问题排查

### 2.6.1 Minikube 启动失败

**问题：** `minikube start` 卡在 `Waiting for cluster to come up...`

**排查步骤：**
```bash
# 1. 检查 Docker 是否正在运行
docker info

# 2. 查看 Minikube 日志
minikube logs

# 3. 删除旧集群重试
minikube delete
minikube start --driver=docker

# 4. 如果仍失败，尝试清理 Docker 缓存
docker system prune -a --volumes
minikube start --driver=docker

# 5. 资源不足时增加等待超时
minikube start --driver=docker --wait-timeout=300s
```

**问题：** 报错 `Error creating machine: Error in driver`

**排查步骤：**
```bash
# 检查 Docker 磁盘空间
docker system df

# 清理空间
docker system prune
docker volume prune

# 重新启动
minikube delete && minikube start --driver=docker
```

### 2.6.2 镜像拉取失败

**问题：** `ImagePullBackOff` 或 `ErrImagePull`

**排查步骤：**
```bash
# 查看 Pod 详细事件
kubectl describe pod <pod-name>

# 常见原因与解决方案：

# 1. 镜像名称错误
# 检查拼写和 tag
kubectl run test --image=nginx:latest --restart=Never

# 2. 私有仓库认证问题
kubectl create secret docker-registry my-registry-secret \
  --docker-server=https://my-registry.com \
  --docker-username=user \
  --docker-password=pass \
  -n default

# 在 Pod 中引用
# spec:
#   imagePullSecrets:
#     - name: my-registry-secret

# 3. Minikube 网络问题
minikube ssh
docker pull nginx:1.25  # 在节点内手动拉取测试

# 4. 国内镜像源问题
# 使用镜像加速
minikube start --driver=docker \
  --registry-mirror=https://registry.cn-hangzhou.aliyuncs.com

# 5. 手动预拉取镜像
minikube ssh
docker pull nginx:1.25
# 然后重新创建 Pod
```

### 2.6.3 端口冲突

**问题：** 启动 Minikube 时提示端口被占用

**排查步骤：**
```bash
# 查找占用端口的进程
lsof -i :8080
lsof -i :30000-30100
lsof -i :10250

# 终止占用端口的进程
sudo kill -9 <PID>

# 或使用其他端口启动
minikube start --driver=docker

# 检查 Minikube 使用的端口范围
minikube service list
```

**问题：** `port-forward` 无法建立连接

**排查步骤：**
```bash
# 确认 Pod 正在运行
kubectl get pods

# 确认 Service 有后端 Pod
kubectl get endpoints

# 检查 Service selector 与 Pod labels 是否匹配
kubectl get svc -o yaml | grep -A5 selector
kubectl get pods --show-labels

# 使用 --address 参数绑定到特定地址
kubectl port-forward service/nginx-service 8080:80 --address=0.0.0.0
```

### 2.6.4 网络访问问题

**问题：** Minikube 中服务无法从外部访问

**排查步骤：**
```bash
# 确认 Minikube IP
minikube ip

# NodePort 访问
curl http://$(minikube ip):30080

# 如果是 macOS Docker 驱动，需要确认端口映射
# Minikube 使用容器作为节点，需要通过 docker port 查看映射
docker port minikube

# 也可以使用 port-forward 绕过网络问题
kubectl port-forward service/nginx-service 8080:80
```

**问题：** Pod 之间无法通信

**排查步骤：**
```bash
# 检查 Pod IP
kubectl get pods -o wide

# 检查 CoreDNS 是否正常
kubectl get pods -n kube-system -l k8s-app=kube-dns

# 测试 DNS 解析
kubectl run -it --rm dns-test --image=busybox:1.36 -- nslookup nginx-service.default.svc.cluster.local

# 如果 DNS 不工作，重启 CoreDNS
kubectl rollout restart deployment coredns -n kube-system
```

### 2.6.5 Kind 特有问题

**问题：** Kind 集群创建失败

**排查步骤：**
```bash
# 1. 确认 Docker 正在运行
docker info

# 2. 清理旧集群
kind delete cluster --name <cluster-name>

# 3. 增加资源限制
# 修改 Docker Desktop 设置，增加 CPU 和内存

# 4. 查看 Kind 日志
kind export logs --name <cluster-name> ./logs

# 5. 网络问题时检查 Docker 网络
docker network ls
docker network inspect kind
```

**问题：** Kind 中 NodePort 无法从主机访问

**排查步骤：**
```bash
# Kind 默认不直接暴露 NodePort，需要配置端口映射
# 使用 extraPortMappings 配置

# 或使用 kubectl port-forward
kubectl port-forward service/nginx-service 8080:80

# 获取内部节点 IP
kubectl get nodes -o wide
# 直接访问（需要端口映射配置）
```

## 2.7 章节小结

### 核心要点回顾

1. **方案选型**：
   - 学习/开发 → Minikube（功能丰富，插件完善）
   - 多节点测试 → Kind（原生支持多节点）
   - 边缘/轻量 → k3s（极致轻量）
   - Docker 用户 → Docker Desktop（零配置）

2. **Minikube 核心命令**：
   ```bash
   minikube start --driver=docker    # 启动集群
   minikube status                    # 查看状态
   minikube stop                      # 停止集群
   minikube delete                    # 删除集群
   minikube addons enable <name>      # 启用插件
   ```

3. **Kind 核心命令**：
   ```bash
   kind create cluster --name <name>  # 创建集群
   kind delete cluster --name <name>  # 删除集群
   kind get clusters                   # 列出集群
   kind load docker-image <img>        # 加载本地镜像
   ```

4. **集群验证三步走**：
   ```bash
   kubectl cluster-info     # 验证 API 连接
   kubectl get nodes        # 验证节点就绪
   kubectl get pods -A      # 验证系统组件
   ```

5. **应用部署流程**：
   ```bash
   kubectl apply -f nginx-deployment.yaml  # 部署
   kubectl get pods -l app=nginx           # 验证
   kubectl port-forward svc/nginx-svc 8080:80  # 访问
   ```

6. **常见问题处理思路**：
   - 启动失败 → 检查 Docker、资源、日志
   - 镜像拉取 → 检查镜像名、认证、网络
   - 访问异常 → 检查端口、网络、Service 配置
